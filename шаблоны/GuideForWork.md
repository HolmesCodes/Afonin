# Инструкция для всех: как работать с моим репозиторием `notes`

Привет! Ты получил доступ к моему приватному репозиторию `notes`, где я храню конспекты, идеи и полезные материалы.  
Чтобы мы не мешали друг другу и ничего не сломали, вот простые правила и инструкции.  
## Если ты не будешь следовать правилам - я ограничу тебе доступ навсегда!

## 📚 Что можно и что нельзя

| ✅ Можно | ❌ Нельзя |
|----------|-----------|
| Просматривать любые папки и файлы | Менять что-либо в ветке `main` |
| Клонировать репозиторий к себе | Пушить в `main` (Это делаю только я) |
| Создавать свои ветки ОТ `dev` | Удалять чужие ветки |
| Добавлять конспекты, идеи, заметки | Редактировать мои файлы без обсуждения |
| Создавать Pull Request в `dev` | Создавать Pull Request напрямую в `main` |
| Исправлять очевидные опечатки | Менять структуру папок без спроса |

## 🚀 Пошаговая инструкция для первого раза

### Шаг 1: Установить Git и GitHub аккаунт

- Установи Git с [официального сайта](https://git-scm.com/downloads)
- Зарегистрируйся на [GitHub](https://github.com) (если ещё нет)
- Сообщи мне свой GitHub-username, я добавлю тебя в коллабораторы

### Шаг 2: Клонировать репозиторий

```bash
git clone https://github.com/Mikhail-69/notes.git
cd notes
```

### Шаг 3: Настроить Git (если не настроено)

```bash
git config --global user.name "Твое Имя"
git config --global user.email "твоя_почта@example.com"
```
## **Начинай от сюда если делаешь не впервые**
### Шаг 4: Переключиться и скопировать текущую ветку `dev`
Все изменения делаем только в dev:
```bash
git checkout dev
git pull origin dev
```
### Шаг 5:  Создать свою ветку для задачи
**Важно**: не работай прямо в `dev`, создавай **свою** ветку:
```bash
git checkout -b твое_имя/что_делаешь
```
Например:
```bash
git checkout -b Ivanov/adding_sql_information
```
### Шаг 6: Сделать изменения
В своей ветке можешь делать что хочешь, любые изменения.
Используй Markdown для форматирования
### Шаг 7: Закоммитить изменения типом Conversial Commits!
Про Conversial Commits можно почитать в ветке main в папке "шаблоны"
```bash
git add .
git commit -m "тип изменения(тема/место): краткое описание изменений"
```
### Шаг 8: Отправить ветку на GitHub
```bash
git push -u origin твое_имя/что_делаешь
```
### Шаг 9: Создать Pull Request (PR)
1. Зайди на https://github.com/Mikhail-69/notes
2. Нажми Pull requests → New pull request
3. Выбери: base = dev, compare = твое_имя/что_делаешь
4. Нажми Create pull request
5. Напиши краткое описание
6. Нажми Create pull request
### Шаг 10: Дождаться ревью
1. Я посмотрю изменения
2. Если всё ок — я солью PR в `dev`
3. Если нужны правки — я напишу комментарии
### Шаг 11: После моего ответа удали ветку (после слияния PR)
```bash
git checkout dev
git branch -d твое_имя/что_делаешь
git push origin --delete твое_имя/что_делаешь
```

## 🤔 Частые вопросы
### Вопрос: Я случайно начал работать в main, что делать?
Ответ: Не паникуй, перенеси изменения в dev:  
```bash
git checkout dev
git merge main
git push origin dev
```
### Вопрос: Могу ли я работать на нескольких компьютерах?
Ответ: Да! Просто не забывай:   
Перед работой: `git pull origin dev`  
После работы: `git push origin твоя_ветка`

### Вопрос: Я хочу предложить новую папку или структуру. Как это сделать?
Ответ:
1. Создай ветку: `git checkout -b твое_имя/new-structure`  
2. Сделай изменения
3. Создай Pull Request в dev
4. Обсудим и решим

### Вопрос: Как удалить свою ветку после слияния?
Ответ:

```bash
git checkout dev
git branch -d имя_ветки          # локально
git push origin --delete имя_ветки # на GitHub
```
## ⚠️ Что делать, если Git ругается
### Ситуация 1: fatal: not a git repository
Проблема: Ты не в папке репозитория.  
Решение: Перейди в папку notes:
```bash
cd /путь/к/notes
```
### Ситуация 2: fatal: pathspec '...' did not match any files
Проблема: Опечатка в названии файла или папки.  
Решение: Проверь точное имя через ls, используй кавычки, если есть пробелы:
```bash
git add "папка с пробелами"
```
### Ситуация 3: Конфликт при слиянии
Проблема: Ты и я изменили один и тот же файл.   
Решение:
1. Открой файл, найди `<<<<<<<`
2. Оставь нужные строки, удали метки
3. Сохрани файл
4. Выполни:

```bash
git add .
git commit -m "resolve: разрешил конфликт"
git push
```
### Ситуация 4: ! [rejected] main -> main (fetch first)
Проблема: На GitHub есть изменения, которых нет у тебя.  
Решение: Сначала забери их:

```bash
git pull origin dev
```
